# apigee-ops

[![CI](https://github.com/gerardrecinto/apigee-ops/actions/workflows/ci.yml/badge.svg)](https://github.com/gerardrecinto/apigee-ops/actions/workflows/ci.yml)

Apigee X operations as code: two proxy bundles, the Terraform that hosts them, certificate renewal into Secret Manager, a capacity planner, a Splunk log report and an Azure DevOps pipeline.

**Site and capacity planner: https://gerardrecinto.github.io/apigee-ops/**

Lab scale. Everything is linted, tested or validated in CI. Nothing has run against a live Apigee organization (see "What is verified").

## What is in it

| Folder | What | Check in CI |
|---|---|---|
| `proxies/orders-api` | JWT verify (RS256, JWKS), spike arrest, environment KVM, response cache that skips error responses, XML to JSON, 404 fault, latency and Splunk logging | apigeelint, 0 errors, 0 warnings |
| `proxies/oauth-token` | OAuth 2.0 client credentials, HTTP Basic decode | apigeelint |
| `terraform/` | Apigee organization, instance, environments, env groups, KVM and entries, target servers, one Secret Manager secret per environment | `fmt -check`, `validate` |
| `src/apigee_ops/certs.py` | Check and renew certs into Secret Manager | 13 tests |
| `src/apigee_ops/capacity.py` | Headroom and days to a planning threshold | tests, plus the JS port must match |
| `src/apigee_ops/logreport.py` | Daily and weekly report from the `ML-Splunk` log line | tests, including a contract test against the policy XML |
| `src/apigee_ops/bundle.py`, `deploy.py` | Reproducible zip, import and deploy through the Apigee API, dry run by default | tests with a fake transport |
| `pipelines/azure-pipelines.yml` | Validate, package, deploy to test, deploy to prod behind approvals | stage order asserted |
| `site/` | GitHub Pages site with an in-browser capacity planner | `node --test` |

## Run it

```bash
git clone https://github.com/gerardrecinto/apigee-ops && cd apigee-ops
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]" && pytest -q
python -m apigee_ops.capacity data/sample_analytics.csv --capacity-tps 100
python -m apigee_ops.logreport data/sample_gateway.log
npx apigeelint -s proxies/orders-api/apiproxy -f table.js
cd terraform && terraform init -backend=false && terraform validate
```

Python 3.11 or newer. The capacity command exits 1 on the sample data on purpose: at 100 TPS the straight-line estimate puts the 80% threshold about a week out. Operational steps are in [docs/RUNBOOK.md](docs/RUNBOOK.md).

## Design choices

- **Cert renewal refuses to go backwards.** It checks the key matches, every hostname is covered and the chain is leaf first, then writes only if the new certificate expires later than the one in the secret. A bad bundle is rejected with reasons and nothing is written. The cost is that an emergency swap to an older certificate needs a manual step. I would relax that only for a documented rollback.
- **Deploy is a dry run by default.** `--apply` is required to send anything. The cost is one more flag in the pipeline.
- **Cache skips error responses.** apigeelint flagged `RC-Orders` for it (PO024). Without it a single 503 from the backend is served from cache for the whole TTL.
- **The log format has a test.** `ML-Splunk.xml` is the one place the log fields are defined, and a test fails if the parser and the policy disagree.
- **Capacity uses a straight line.** It is easy to explain and to check by hand. Traffic with weekly seasonality or a launch will not fit a line, and the report says so by being wrong; use it as an early warning, not a forecast.

## What I hit building it

- apigeelint rejected my first drafts: a response cache that cached errors, a deprecated `TimeoutInSec`, a policy name that broke the VerifyJWT naming rule, and single-quoted strings in the JavaScript resource.
- `google_apigee_environment_keyvaluemaps` has no `encrypted` argument in the provider; `terraform validate` caught it.
- `cryptography` has no wheel for Intel macOS on Python 3.14, so the local environment uses Python 3.12 and `pip install --only-binary=:all:`. CI uses 3.12.

## What is verified

Linted: both proxy bundles. Validated: Terraform, never planned or applied. Tested: Python modules with generated certificates, an in-memory secret store, synthetic analytics and logs, and a fake HTTP transport. Parsed only: the Azure DevOps pipeline, which has not run on an agent.

Not done: any run against a real Apigee X organization, the Secret Manager client in CI, Postman and JMeter suites, Apigee Hybrid, and API products, developer apps or analytics export. The sample data is synthetic and generated by `data/make_sample_data.py`.
